## 修改清单

### #1 — C4/CARVE — puzzle_token_str_eq 填充字节错误 (byte-identical 关键)

ROM 0x09e4748c 处：`=` 字符串块大小 = 4 字节（`0x3d 0x00 0x00 0x00`）。

提案：
```asm
puzzle_token_str_eq:
    .asciz "="
    .byte 0x00, 0x00, 0x00 @ pad
```
`.asciz "="` = 2 字节 (0x3d + NUL) + 3 pad = **5 字节**。超出 1 字节。

正确写法：
```asm
puzzle_token_str_eq:
    .asciz "="
    .byte 0x00, 0x00        @ pad (2 bytes only)
```
验证：1 (char) + 1 (NUL) + 2 (pad) = 4 字节 = ROM 块大小。

### #2 — C4/CARVE — puzzle_token_str_captured 终止符错误 (byte-identical 关键)

ROM 0x09e47554 处：`CAPTURED` 填满至 0x09e4755b（8 字节，无 NUL，无 padding）。carve 区域在 0x09e4755c 结束。0x09e4755c 处的 `0x00` 属于 after-incbin 区域第一字节。

提案：
```asm
puzzle_token_str_captured:
    .asciz "CAPTURED"
    .byte 0x00, 0x00, 0x00, 0x00 @ pad
```
`.asciz "CAPTURED"` = 9 字节 + 4 pad = **13 字节**。超出 5 字节。

正确写法：
```asm
puzzle_token_str_captured:
    .ascii "CAPTURED"          @ 8 bytes, NO NUL terminator within carve
```
验证：8 字节 = ROM 块大小。NUL 终止符来自 after-incbin 的第一字节（0x09e4755c = `0x00`）。

总 carve 超出：Issue #1 + Issue #2 = 1+5 = **6 字节** (254 组装 vs 248 ROM)。两处均导致 byte-identical 失败。
