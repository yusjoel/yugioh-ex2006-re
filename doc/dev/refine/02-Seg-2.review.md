## 附记: 独立复核发现的细节 (不影响 PASS)

以下为细节发现，均属**文档注释级别偏差**，不影响 byte-identical 落地，fixer 落地时注意即可：

### N1 — 文档计数偏差 (C13 说明用)

Proposal 称"94 个 DAT_/DWORD_/PTR_ 定义 … - 2 (INCBIN) - 4 (PTR_gP1LifePoints) = 88"，但独立 grep 实际得 96 个标签（净 90 个）。差值 2 来自实际存在但 proposal 未列入总计的 2 个标签（已被 EQ/REF/RENAME 表正确覆盖）。覆盖完整，总数文档有误不影响落地。

### N2 — 分发表条目数注释偏差 (C2 说明用)

Proposal 多处称"9-entry phase dispatch table at 0x0802e20c"。独立核查：
- CMP r0,#7 at 0x0802e1f0（边界检查 phase 0..7）
- Table 0x0802e20c + 8*4 = 0x0802e22c = Block 1 起始
- 实际为 **8 entries**（index 0..7），entry[0]=0x0802e3c8(LAB fallthrough), [1..4]=0x0802e22c, [5]=0x0802e23c, [6]=0x0802e324, [7]=0x0802e2c4

ref-scan 结果：Block 1 entry point 0x0802e22c = 4 raw refs（entries [1,2,3,4]）正确。Block 1 size 0x19c 正确。这是 Ghidra 注释的条目数偏差（Ghidra 可能将 entry[0] 的目标 0x0802e3c8 也算入，或多计了 1），不影响 disasm 落地方案正确性。

### N3 — 0x0802e420 (gPrng) 表格归类

DWORD_0802e420 = 0x03000040 (gPrng) 在 EQ_SLOTS 表中未单独成行，但在 REF_SLOTS 表第 3 行（"gPrng (已有 label) … EQ gPrng"）中有完整处理计划，slot_label = tick_campaign_prng_ctx。覆盖正确，表格布局稍混但不影响落地。
