### ref-scan 结果 (自行重跑)

ROM_INCBIN 块 0x08027e50 / 0x6c:

- raw (word-pointer) refs = 0
- THUMB+1 refs = 0
- BL 调用者 (THUMB->THUMB, BL 前缀 0xF000 + 后缀 0xF800) = **18 hits**, 全部命中 proposal 列出的地址:
  `0x08029478, 0x080294c0, 0x08029554, 0x080295a4, 0x08029d38, 0x08029e0a, 0x08029e38, 0x08029fac, 0x0802a19c, 0x0802a3b0, 0x0802a40c, 0x0802a492, 0x0802a4c8, 0x0802a784, 0x0802a83c, 0x0802a89c, 0x0802aa38, 0x0802aa92`

块首字节 0xb5f0 = `push {r4-r7, lr}` THUMB 序言, 确认为 THUMB 函数体。

### 求助项裁定

**(1)(2) pack GFX assets 0x09b9e6e8 等 (Carve G) + campaign_hand_oam_array 0x095b7cca (Carve H)**

**pack GFX (Carve G)**: 阻塞理由有误。5 个地址均在 rom.s line 660 的现有 incbin 内, 可以 carve。但 carve 需要知道每个 asset 的精确大小 (pack_bg_tile_data/palette_data/tiles_a/b/c 的大小取决于 GFX format 分析)。fixer 应: ① 更正提案中的 BLOCKED 理由 ("asset sizes unknown" 而非 "not in rom.s"); ② 在确认大小后对 rom.s line 660 的 incbin 做分裂 carve; ③ 在完成 carve 前, 对 5 个 REF_SLOTS 改用 RENAME 处置 (slot 改为描述性名称如 load_pack_tiles_with_palette_init_tiles_a 指向裸地址), 待后续 carve 补全 REF。

**campaign_hand_oam_array (Carve H)**: 0x095b7cca 落在 data/card-image-index.s 自动生成文件内 (ROM 0x15B5C00..0x15B7CCC)。该文件不可手动添加标签 (auto-gen), 且 22 raw refs 表明它是被引用数据。正确处置: RENAME 槽 (slot 改为 run_campaign_card_select_handler_13_hand_array 描述性名), 不尝试 carve 到 auto-gen 文件内。提案 RENAME 方案方向正确, 但阻塞理由 ("large gap") 同样不准确。

**裁定结论**: Carve G/H 作为 RENAME 处置 (以描述性 slot 名指向裸地址) 是当前阶段的可接受降级处置, 但 proposal 必须修正错误的 BLOCKED 理由, 且必须移除 5 个 pack_tiles_* 的 REF_SLOTS 条目 (因为对应标签不存在)。

**(3) GPRNG_OAM_ATTR_FIELD_OFF = 0x20c 语义裁定**

DWORD_0802891c 持有绝对 IWRAM 地址 0x0300024c = gPrng+0x20c。代码中以绝对地址加载后用作表基指针 (ldrh [r9, #slot_off])。**此槽的正确处置是 REF** (如提案 REF_SLOTS 表所示): 在 gPrng+0x20c 处创建 USER label, 从该槽添加 DATA ref。

**GPRNG_OAM_ATTR_FIELD_OFF = 0x20c 的 EQ_NEW 申请应撤回**: Seg-9 内无任何 literal pool 槽持有值 0x20c, 该常量在本段无使用点, 不应新建。若未来有代码用 0x20c 作即时偏移 (如 THUMB `adds r,r,#GPRNG_OAM_ATTR_FIELD_OFF`) 可届时另行创建。名称本身 (med-conf 标注) 可接受, 但现在不应新建。
