## 修改清单

### #1 — C4 — GBA_VRAM_BASE 标注错值 (0x06004000)

**问题**: 槽 `0x0802cd9c` 和 `0x0802d170` 的值均为 `0x06004000`，proposal 用名 `GBA_VRAM_BASE`。  
但 `gba_mem.inc` 中 `GBA_VRAM_BASE = 0x06000000`（BG/OBJ VRAM 起始）；`0x06004000 = BG_CHAR_VRAM_CB2`（charblock 2 基址，已在 `gba_mem.inc` 中定义，43 ROM refs）。

**修正**: 两槽均改用 `BG_CHAR_VRAM_CB2`（EQ_REUSE）。

```
0x0802cd9c: EQ_REUSE BG_CHAR_VRAM_CB2   (not GBA_VRAM_BASE)
0x0802d170: EQ_REUSE BG_CHAR_VRAM_CB2   (not GBA_VRAM_BASE)
```

### #2 — C4/C6 — PACK_INFO_BG2CNT_INIT 名称碰撞 (0x8208 vs 存在 0x820a)

**问题**: 槽 `0x0802cd94` = `0x00008208`，proposal 命名为 `PACK_INFO_BG2CNT_INIT`。  
但 `gba_mem.inc` 中已有 `.equ PACK_INFO_BG2CNT_INIT, 0x0000820a`（不同值！）。  
GAS 中同名 `.equ` 重复定义会报错或静默覆盖，破坏 byte-identical。

**修正**: 为 `0x8208` 新建独立名，如 `RESULT_SCREEN_BG2CNT_INIT`（需确认 C5 无同值常量）：
```
0x0802cd94: 新名 RESULT_SCREEN_BG2CNT_INIT = 0x00008208
```
`0x8208 = BG2CNT: pri=0 charbase=2 mosaic=0 16col scrbase=2 size=0`（与 `0x820a` 相差位2）。
