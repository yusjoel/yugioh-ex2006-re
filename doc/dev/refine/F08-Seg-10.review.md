## 修改清单

### #1 — C6 — Block4 (0x0806e460/0x1cc) 全部 6 个 de_fusion stub 名 state 后缀倒置

**严重程度**: hard NEEDS_FIX（函数名与调度 state 完全对不上）

**根因**: 提案将 table entry[0] 的函数命名为 `de_fusion_state_stub_80`，但 dispatcher 的 index = state - 0x7b，entry[0] 对应 state=0x7b（非 0x80）。Block4 的表项按 stub 地址降序存储（entry[0]=0x6e618 是最高地址），提案误以为地址顺序=state顺序，导致全部反转。

**正确映射**（python 实读 table at 0x6e448 + dispatcher `subs r1,#0x7b` 核实）:

| `de_fusion_state_stub_7b` | 0x0806e618 | 0 | 0x7b | de_fusion_state_stub_80 |
| `de_fusion_state_stub_7c` | 0x0806e5d4 | 1 | 0x7c | de_fusion_state_stub_7f |

### #2 — C12 — Advisory: DISPCNT_SHADOW=0x04000400 名有误导性（不阻塞）

**严重程度**: advisory（不强制阻塞，但建议改名）

**问题**: 0x04000400 超出 GBA I/O 寄存器有效范围（DISPCNT=0x04000000，I/O 范围上限 0x040003FE）。该值作为 r1 传给 `query_equip_target_bitmap_default(slot_ptr, r1)` → `update_equip_target_bitmap_for_field`，不是硬件寄存器地址访问模式（无 str/ldr 到此地址），更像是游戏内部位图查询 key/mask。名称 DISPCNT_SHADOW 暗示硬件影子寄存器，语义不正确。

**建议改名**: `EQUIP_BITMAP_QUERY_KEY` 或保持中性 `EQUIP_BITMAP_PARAM_04000400`，放 gba_io.inc 或新增 equip_bitmap.inc。

**fixer 决策权**: 若保留 DISPCNT_SHADOW（plate 来源），须在 plate 注释中加 `(game-specific, not a real HW shadow reg)` 澄清。可接受任一方案后 PASS。
