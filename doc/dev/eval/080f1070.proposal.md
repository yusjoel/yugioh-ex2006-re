# Naming Proposal: 0x080f1070

## 提案
- **proposed_name**: blit_glyph_col_to_buffer
- **confidence**: high

## plate comment (中文)
由 render_glyph_jp_single_layer (0x080f19a4) 在逐字符渲染循环中每字符调用 6 次, 每次处理字形一列像素的写入. 以 10 次行迭代 (r5=0..9) 遍历字形高度, 对列像素掩码 (10-bit bitmask, 经高位寄存器传入) 中每个置位行计算 VRAM tile 字节偏移, 按 [0x02006ed0+0x15] bit3 区分 4bpp (nibble read-modify-write) 与 8bpp (byte write) 两路, 将颜色值写入 EWRAM 字形缓冲区. 是 blit_glyph_row_to_buffer (0x080f0f70) 的列方向对称体, 行处理 8 像素改为列处理 10 行.

## 参数签名
- r0: u8 color_nibble — 4bpp 颜色索引 (0x0–0xF); 4bpp 路径作 nibble 写入，8bpp 路径直接作字节值
- r1: i32 x_pos_minus1 — 字形 X 起始坐标减 1 (用于 `subs r1,#0x1; ands r4,r0` 计算 x_within_tile = (x_pos-1) & 7)
- r2: i32 col_byte — 列字节索引 (`r2 >> 3` 得 VRAM 列字节偏移, 存 sp+0)
- r3: ptr gfx_ctx — 指向 0x02006ed0 全局字形渲染上下文 (EWRAM)
- 高寄存器 r8: ptr gfx_ctx (同 r3, 通过 `.hword 0x469a = mov r10, r3` 和后续传递保存)
- 高寄存器 r12: u16 col_pixel_mask — 10-bit 列像素掩码 (bit9..bit0 对应行 0..9, 置位 = 该行有像素)
- 返回: void (无返回值, 仅副作用)

## 副作用
- [EWRAM 0x02006ed0+0x0] 读取: VRAM tile 缓冲区基地址 (ptr)
- [EWRAM 0x02006ed0+0x8] 读取: VRAM tile 宽度 (halfword, bits [13:8] 提取后得 tile_cols 数量)
- [EWRAM 0x02006ed0+0x15] 读取: 字形渲染模式标志字节 (bit3=1 → 4bpp 路径, bit3=0 → 8bpp 路径)
- **4bpp 路径** `strb r2,[r3,#0x0]` @ 0x080f1116 — 对 col_pixel_mask 每个置位行, 写 nibble-merged 字节到 VRAM 字形缓冲区 ([VRAM_base + row_offset + x_byte]); 先 ldrb 读旧值再 ands/orrs 混合，确保相邻 nibble 不被覆盖
- **8bpp 路径** `strb r0,[r2,#0x0]` @ 0x080f115e — 对 col_pixel_mask 每个置位行, 写字节到 VRAM 字形缓冲区 ([VRAM_base + row_stride_offset + x_col_offset])

## 行级注释 (≤ 30 行精华, 按 ROM 地址排)
- @ 0x080f107c: `mov r10, r3` — 保存 gfx_ctx 指针到 r10 (高寄存器, 循环中不被 r3 覆盖)
- @ 0x080f107e: `lsls/lsrs r0,r0,#0x18` — r0 = r0 & 0xFF, 截取 color_nibble 为无符号字节
- @ 0x080f1084: `subs r1,#0x1` — 求 x_pos - 1 (注: 偏移从 -1 开始是为对齐 3 列扩展写入的中心列)
- @ 0x080f1086: `movs r0,#0x7; ands r4,r0` — r4 = (x_pos-1) & 7 = x-within-8px-tile
- @ 0x080f1094: `asrs r6,r1,#0x3` — r6 = (x_pos-1) >> 3 = x_tile_col (横向 tile 索引)
- @ 0x080f1096: `asrs r2,r2,#0x3; str r2,[sp,#0x0]` — column_byte_offset = col_byte >> 3, 存入栈 (8bpp 路径用)
- @ 0x080f10a8: 读 `DAT_080f112c = 0x02006ed0` — 每次循环体内重加载 gfx_ctx 基址 (避免高寄存器污染)
- @ 0x080f10aa: `movs r0,#0x8; ldrb r3,[r2,#0x15]; ands r0,r3` — 提取 mode_flags bit3 = 4bpp 标志
- @ 0x080f10c6: 循环头 r5=0..9 — 迭代 10 行 (JP 字形有效高度 = 10 像素; 对比 blit_glyph_row_to_buffer 迭代 8 列)
- @ 0x080f10c8: `movs r0,#0x80; lsls r0,r0,#0x2` — r0 = 0x200 = bit9 初始掩码 (10-bit, 对应第 0 行)
- @ 0x080f10ca: `asrs r0,r5` — r0 = 0x200 >> r5 = 当前行的掩码位
- @ 0x080f10ce: `ands r0,r3` — 测试 col_pixel_mask (r3=r12 via mov) 中当前行是否有像素
- @ 0x080f10d8: `ldrh r1,[r1,#0x8]` — 读 gfx_ctx.tile_width (halfword at offset +8)
- @ 0x080f10da: `lsls r0,r1,#0x16; lsrs r0,r0,#0x18` — 提取 tile_cols = (tile_width >> 2) & 0xFF
- @ 0x080f10e0: `muls r0,r2` — row_y_offset = tile_cols * column_byte_offset
- @ 0x080f10e2: `adds r0,r6,r0; lsls r0,r0,#0x6` — tile_row_stride = (x_tile_col + row_y_offset) * 64 (每 tile 行 64 字节)
- @ 0x080f10e8: `ldr r3,[r1,#0x0]` — 读 VRAM 缓冲区基地址
- @ 0x080f10ec: `lsrs r0,r4,#0x1f; adds r0,r4,r0; asrs r0,r0,#0x1` — r0 = floor(r4 / 2) = x_nibble_byte (4bpp: 两 nibble 共享一字节)
- @ 0x080f10fe: `lsls r0,r4,#0x2` — 4bpp nibble shift: r4 (x & 1) * 4 = 0 或 4 (低/高 nibble)
- @ 0x080f1102: `lsls r2,r0` — 准备颜色 nibble 移位到正确位置
- @ 0x080f110c: `movs r0,#0xf; lsls r0,r1` — 生成 nibble 清除掩码 (0xF << shift)
- @ 0x080f1110: `ldrb r1,[r3,#0x0]; ands r0,r1` — 读旧字节, 保留另一个 nibble
- @ 0x080f1114: `orrs r2,r0` — 合并新 nibble 与保留的旧 nibble
- @ 0x080f1116: `strb r2,[r3,#0x0]` — **写 nibble-packed 字节到 VRAM** (4bpp 路径核心副作用)
- @ 0x080f1118: `adds r4,r7,#0x0` — x_within_tile = x_within_tile_next (更新 x 位置)
- @ 0x080f111a: `cmp r4,#0x7; ble ...; movs r4,#0x0; adds r6,#0x1` — x_within_tile 环绕时递增 tile_col
- @ 0x080f1122: `adds r5,#0x1; cmp r5,#0x9; ble` — 行循环控制, 共 10 行

## 调用图
- 调用方 (caller): render_glyph_jp_single_layer (0x080f19a4) — 每字符在 4bpp 分支调用 6 次 (3列 × 2行半字), 处理 JP 字形的列向像素写入
- 调用 (callee): 无 (纯叶子函数, 仅 VRAM 写入操作)

## 置信度证据
- **high**: 层 3 (数据 label 反推) — `[0x02006ed0]` = 全局字形渲染上下文, 已在 font_jp 模块多处确认; 函数行为与 blit_glyph_row_to_buffer (0x080f0f70) 结构完全对称, 唯一差异为迭代方向 (行→列) 和循环次数 (8→10)
- **high**: 层 6 (调用图 hub) — 唯一调用方 render_glyph_jp_single_layer 已确认为 8bpp 单层 JP 字形渲染器; 在 4bpp 分支路径下调用 6 次正好对应 12px 宽 JP 字形的 6 列段
- **high**: 层 2 (副作用分析) — `strb` 目标地址由 `[0x02006ed0+0x0]` (VRAM base) + 行/列偏移计算得出, 属于 EWRAM 字形 tile 缓冲区; 两路分支 (4bpp read-modify-write nibble / 8bpp direct byte) 与 mode flag bit3 一一对应
- 兄弟函数矩阵印证: blit_glyph_row_to_buffer (0x080f0f70) 处理行 (8 次), 本函数处理列 (10 次), 二者在同一 render_glyph_jp_single_layer 内互为分支, 命名对称性强
