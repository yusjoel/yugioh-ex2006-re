## plate comment (中文, ASCII 标点)
计算装备卡 r0 可合法放置到对方场地槽位的数量, 同时兼顾装备链配对约束.
进入时先以固定卡 ID 0x13f2 调用 count_field_copies_of_card, 若场上已存在则直接返回 0 (禁止重复放置).
通过双重循环遍历场地槽位 (外层 player=0..1, 内层 slot=0..4):
(1) 检查槽位激活标志 (lsls #0x13 active bit);
(2) 调用 check_slot_equip_eligibility 确认槽位可装备;
(3) 若槽位在特定范围 (r10 in [DAT_080339d4-5..DAT_080339d4]) 且 r2!=0, 则进入装备链配对逻辑:
    遍历已存在的装备节点, 调用 get_paired_card_id_by_variant 匹配变体 card_id,
    再调用 find_equip_chain_node_by_slot_pair 检查配对节点是否已存在;
    符合条件则通过 check_equip_cards_share_field7 累加计数.
返回合法放置总数 (0 表示无法放置或已有重复).
Constants: card_id_guard=0x13f2, gDuelFieldSlots=0x0201c510, player_stride=0x868, slot_range_max=0x164f, slot_entry=0x14.

## 参数签名
- r0: u16 card_id 待放置的装备卡 ID [0..0x1fff]
- r1: (入口时被 .hword 0x468a 覆盖; 实际为 callee-save r10 传递) -- 见 non-APCS 说明
- r2: u32 chain_check_flag 是否执行装备链配对检查 [0=跳过配对, 1=执行]
- r8 (non-APCS, caller-set): u32 equip_player_side [0..1] (在 check_slot_equip_eligibility 及内层 bl 前使用)
- r10 (non-APCS, caller-set): u32 target_slot_idx -- 用于槽位范围过滤 [0..4]
- 返回: r0 = u32 count 合法装备放置数量 [0..10]; 0 = 无法放置
