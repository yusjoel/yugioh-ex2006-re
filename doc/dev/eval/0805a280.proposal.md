# Naming Proposal: 0x0805a280

## 提案

- **confidence**: high

## plate comment (中文, ASCII 标点)
在栈上构造 0x18 字节装备查询 context_struct 并委托激活评估. 入口: memset 0x18 字节; 从 gDuelFieldSlots[player][slot] 读取 card_id 低 13 位写入 [sp+0x0] hword; card_id==0 -> 立即返回 0. 将 r1 bit0 (player_id) 写入 [sp+2] bit0; 从 r2 (slot_idx [0..4]) 提取 bits[0..4] << 1 写入 [sp+2] bits[6:1]; 读 gDuelFieldSlots[player][slot] bits[25:18] (zone_type) << 1 | bit18 (side_bit) 写入 [sp+4] bits[13:6]. 检查 gDuelFieldSlots[player][slot][+8] (active_hword); ==0 -> 调 check_card_zone_activation_blocked(sp_ctx, r1=slot) 返回其结果; !=0 -> 调 eval_equip_activation_for_slot(sp_ctx). 是装备激活检查的 context 组装层.

## 参数签名
- r0: u32 player_side_primary [0..1] -- 写入 r8; 用于 [gDuelFieldSlots+0x1d78] eors 比对
- r1: u32 player_id [0..1] -- 全 5 个 callsite 均传 player_id: @ 0x08085874 `adds r1,r6,#0` r6=player 循环计数 [0..1]; @ 0x0808598c 同上; @ 0x080968d6 `adds r1,r4,#0` r4=caller 入参 player_id; @ 0x080b4ca4 `adds r1,r5,#0` r5=caller 入参 player_side; @ 0x08096846 r5=0 (常量 player_id=0); 函数内部 `ands r2,r6` (r6=r1) 提取 bit0 写入 [sp+2] bit0; 与 r0 player_side_primary 语义区分: r0 用于 gDuelFieldSlots eors 比对选 side, r1 决定 [sp+2] bit0 字段
- r2: u32 slot_idx [0..4] -- callsite asm: @ 0x080968d0 `adds r2,r1,r3` (zone_type+lp_threshold 合成槽偏移); 用于 `lsls r0,r5,#2; adds r0,r0,r5; lsls r0,r0,#2` = slot_idx*20 slot_entry 偏移
- 返回: r0 = u32 bool (1=可激活, 0=不可激活)

## 副作用
- [sp..sp+0x18]: 栈临时 context_struct (函数返回后销毁)
