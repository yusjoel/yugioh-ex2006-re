# Naming Proposal: 0x080f42b4

## 提案
- **proposed_name**: init_font_jp_render_context
- **confidence**: high

## plate comment (中文)
由多个 text-box setup 函数（FUN_08017798 / FUN_08019820 等）在页面初始化阶段调用，负责将全局 font_jp 渲染上下文 (EWRAM 0x02006ed0, 104 字节) 清零后写入三项核心参数：VRAM 目标基址、水平方向 tile 数（width_tiles）、垂直方向 tile 数（height_tiles）。同时查询 EWRAM[0x02006c2c] 低 3 位确定 bpp/语言模式标志，从 font_jp_base_table 选出对应的渲染函数指针写入 context[+0x04]，最后在 context[+0x15] 置位 bit4（0x10）标记初始化完成。调用方随即修改 context[+0x08] 低位和 context[+0x15] 其它位完成各自的显示模式配置。

## 参数签名
- r0: `ptr VRAM_base` — VRAM 目标区域首地址（如 `0x06000020`、`0x06010000+offset`，BG tilemap 区段起点，4 字节对齐）
- r1: `u8 width_tiles` — 文字绘制区域水平宽度（单位：tile，典型值 0x0a..0x1b，如 0x16=22, 0x19=25, 0x1b=27, 0x18=24）
- r2: `u8 height_tiles` — 文字绘制区域垂直高度（单位：tile，典型值 0x02..0x15，如 0x0c=12, 0x0b=11, 0x15=21, 0x02=2）
- 返回: void（无返回值，仅副作用写入 EWRAM 上下文结构）

## 副作用
- `[0x02006ed0..+0x67]` := 0x00000000 × 26 words（bios_cpu_set fill 模式，清零全部 104 字节 font_jp 渲染上下文结构体）
- `[0x02006ed0+0x00]` := r0（VRAM 目标基址）
- `[0x02006ed0+0x04]` := `font_jp_base_table[idx]`（渲染函数指针，idx 由 context[+0x08] bits[1..2] 决定）
- `[0x02006ed0+0x08]` bits[2..9] := width_tiles & 0xff（水平 tile 数写入 bits 2-9）
- `[0x02006ed0+0x08]` bits[10..17] := height_tiles & 0xff（垂直 tile 数写入 bits 10-17）
- `[0x02006ed0+0x08]` bit0 := (`[0x02006c2c]` & 0x7) != 0 ? 1 : 0（bpp/语言模式标志）
- `[0x02006ed0+0x0a]` bits[2..15]: 由 height 派生字段写入（VRAM 行节距相关）
- `[0x02006ed0+0x0b]` bits[4..7]: 由 context[+0x08] bits[14..17] 写入（height 高 nibble）
- `[0x02006ed0+0x0c]` bits[0..5]: 由 context[+0x08] bits[18..23] 写入（height 衍生 pitch）
- `[0x02006ed0+0x14]` := 0x00（清除渲染状态字节）
- `[0x02006ed0+0x15]` := 0x10（set bit4，初始化完成标志）
