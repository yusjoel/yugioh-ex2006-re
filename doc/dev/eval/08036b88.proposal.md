# Naming Proposal: 0x08036b88

## 提案
- **proposed_name**: find_effect_entry_by_player_zone
- **confidence**: med

## plate comment (中文, ASCII 标点)
在决斗效果条目数组 (基址 0x0201b590, 24 字节/项, 项数由 gDuelPhaseFlags+0x594 存储) 中逆序线性搜索, 查找 player_side (bit0) 和 zone_type (bits[1..5]) 与入参均匹配的条目. 对每个候选条目调用 FUN_08080d6c(entry_ptr, inner_idx) 读取格位状态编码, 再与打包键 (player_side | slot_idx<<8) 比较; 内层循环从 0 到条目内子项数-1. 全部条件满足返回 1, 遍历结束未命中返回 0. 唯一调用方 FUN_0803a7f0 在双层格位扫描中, 已先确认格位有有效卡牌, 再调本函数查找对应效果条目.

Constants:
- gDuelPhaseFlags = 0x0201b290
- effect_entry_count = [gDuelPhaseFlags + 0x594] (0x0201b824)
- effect_entry_array = 0x0201b590 (stride = 0x18 bytes)

## 参数签名
- r0: u32 player_side [0..1] (bit0 筛选条目; 也作打包键低字节)
- r1: u32 slot_idx [0..4] (spill 到栈 sp+0; 作打包键高字节)
- r2: u32 player_side_copy [0..1] -> r10 (bit0 用于二次匹配; 一般 == r0)
- r3: u32 zone_type [0..0x1f] -> r9 (与条目 bits[1..5] 比较)
- 返回: r0 = u32 bool (1 = 找到匹配条目; 0 = 无匹配)

## 副作用
- 无外部写入, 纯只读查表

## 置信度证据

- 层 2 (callee): FUN_08080d6c 读 entry_ptr+idx*2+8 处 word 并提取 bit0 + bits[1..4]
- 层 3 (caller 模式): 调用前已调 get_slot_card_state_code / compute_slot_zone_eligibility_mask, 本函数是对效果条目数组的匹配层
