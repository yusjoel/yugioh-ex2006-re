# Naming Proposal: 0x0804f0e4

## 提案
- **proposed_name**: flush_sprite_row_queue_partial
- **confidence**: med

## plate comment (中文, ASCII 标点)
将 sprite row 动画队列中已完成但未写出的条目向前紧缩 (compact) 并触发剩余条目写出.
基地址 0x0201b290 (DAT_0804f1cc), 队列计数存于 +0x488 (= 0x91 << 3), 队首写指针存于 +0x480 (= 0x90 << 3).
当前读指针 < 队列深度时: 以 copy_bytes_by_halfword 将 0x18 字节条目从源复制至目标, 更新写指针, 递增帧号直到超出 0xf 上限.
写指针达上限后: 进入第二阶段, 将尾部条目向前移动 (compact 残余), 更新计数字段 [base+0x488] -= processed_count.
最终清零 [base+0x490] 和 [base+0x494] 表示队列已刷新就绪.
调用方: FUN_0804f2e0 (tags: card_frame/duel_field/game_str, 动画帧完成后调用本函数刷新 sprite 行队列).

Constants: base=0x0201b290, write_ptr_offset=0x480 (0x90<<3), count_offset=0x488 (0x91<<3), max_row=0xf, entry_stride=0x18.

## 参数签名
- 无 APCS 输入参数 (入口 ldr r1,DAT_0804f1cc 加载 base, 未读 r0-r3; 入口 .hword 0x464f=mov r15,r1 / 0x4646=mov r14,r6 为 callee-save)
- 返回: r0 = u32 (0=未处理任何条目 / 1=处理完成)

## 置信度 / 升级路径
- 静态已确认: base+0x488 字段语义 = pending_count (待处理条目计数). 证据: @0804f102 ldrh 读取 [base+0x488] 作为循环上限 (cmp r4,r0; bge 退出); @0804f18e str (count - processed) 写回, 即 pending -= 已处理数. 命名 count_offset 已正确反映该语义.
- 静态已确认: 函数返回 1 的准确条件 (路径 @ 0804f1ba) -- 静态追踪: 0804f1a0 ldrh r4,[base+0x480] 读写指针; 0804f1a2 rsbs r0,r4,#0 (= -write_ptr); 0804f1a4 orrs r0,r4 (= (-write_ptr | write_ptr)); 0804f1a6 lsrs r0,r0,#0x1f (提取 bit31). 结论: write_ptr==0 时 bit31=0 返回 0; write_ptr!=0 时 (-x|x) bit31=1 返回 1. 即: "写指针非零则返回 1 (有已处理条目), 否则返回 0".
