## plate comment (中文, ASCII 标点)
对卡牌放置请求执行综合规则检查, 依次验证: (1) find_paired_zone_entry_for_card(配对区域条目是否合法), (2) 场地卡份数限制(check_card_field5_is_nonzero + FUN_0802fc90), (3) find_effect_node_in_zone(效果区域节点占用检查), (4) get_card_field_summon_restriction(场地依赖召唤限制 ID 判断), (5) get_card_extended_stat_field6/9(扩展属性过滤), (6) check_card_is_zone_pair_restricted(配对限制双牌检查), (7) get_card_effect_zone_check_sides(效果区侧位需求掩码 + count_available_effect_zones 双路检查). 任意一路规则触发则在 gP1LifePoints 关联的玩家状态中写入标志并返回 1; 全部通过则返回 0. r8 为 caller 传入的玩家状态基地址(非 APCS 隐式参数).

## 参数签名
- r0: ptr card_info -- 卡牌放置信息结构体指针; [r0+0]=card_id(u16), [r0+2]=byte(bit0=player_side, bits[5:1]=zone_index), [r0+3]=byte(flag bits), [r0+4]=zone_type_fields
- r8: ptr player_state_base -- 玩家状态基地址, caller-set 非 APCS 参数; callsite 0x0805a4ec: `.hword 0x4646` (mov r6,r8) 紧邻 `bl FUN_0805aea4` 且 FUN_0805aea4 未重写 r8 直接透传至 bl FUN_0805a9a8
- 返回: r0 = u8 -- 0=所有规则通过(放置允许), 1=规则触发(放置被阻断并写入玩家状态)

## 副作用
- [gP1LifePoints + 0x1d78]: 当 LAB_0805ae78 路径触发且 r7(adjusted_player_side)==[0x0201e2a0+4] 时写入 0x14(=20)(玩家状态标志)
