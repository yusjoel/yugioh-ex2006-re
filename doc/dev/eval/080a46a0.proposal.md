## plate comment (中文, ASCII 标点)
AI 放置决策核心函数: 针对玩家 r5 场上已有的 card_id r4 (low 13 bits 提取自 gDuelFieldSlots),
综合多个维度评估是否可以/应该放置该卡, 返回放置建议标志位集合 r6.
入口通过 .hword 0x4692 (mov r2,r10) / .hword 0x4680 (mov r0,r8) 读取 non-APCS 参数.
主流程:
(1) 若 card_id==0 或 check_card_field5_is_nonzero 失败 -> 返回 0;
(2) check_card_targeted_by_spell_zone_effect 检查是否被场效果指定;
(3) check_lp_exceeds_spell_copy_threshold / check_card_not_equip_placement_type 等多重 guard;
(4) count_field_copies_of_card(0x135d) guard: 已有副本则特殊处理;
(5) 根据 card_id 的大型 BST dispatch (0x14db/0x16ec/0x1386/0x164f..0x1691..0x1838.. 等):
    各分支分别调用 check_field_spell_card_placeable_strict / check_field_spell_group_placeable /
    eval_equip_targets_for_card / count_available_monster_slots / FUN_080338b8 /
    check_player_can_place_card / check_equip_card_activation_valid / count_paired_slots_with_field5_default 等;
    将结果通过 orrs r6,rX 积累到 r6 (bit 位标志);
(6) 最终将 r6 作为放置建议标志返回.
调用方 FUN_0805d0ca / 0x080961?? / 0x080b1186 等 AI 主循环.
Constants: gDuelFieldSlots=0x0201c510, gP1LifePoints=0x0201c4e0, player_stride=0x868, FIELD_SPELL_ZONE=0xb, guard_card_id=0x135d.

## 参数签名
- r5 (non-APCS, caller-set): u32 player_side 玩家编号 [0..1]
- r4 (non-APCS, caller-set): u16 card_id 待评估的卡 ID [0..0x1fff] (从槽位字 low 13 bits 读取)
- r8 (non-APCS, caller-set): u32 player_side (与 r5 对应, 传递给子函数)
- r10 (non-APCS, caller-set): u32 slot_data 槽位数据
- sp[0]: u32 additional_flag 附加标志位
- 返回: r0 = u32 placement_flags 放置建议标志位集合 (0=不放置)
