# Naming Proposal: 0x080f1180

## 提案
- **proposed_name**: blit_glyph_row_colored
- **confidence**: high

## plate comment (中文)
由 render_glyph_jp_single_layer (0x080f19a4) 在逐字符渲染循环中按字符高度的一半 (每字符 2 次) 调用, 仅在渲染上下文要求显式色彩覆盖时激活 (调用方 sp+0x8 标志非零时分派到本函数, 为零则改调 blit_glyph_row_to_buffer). 与 blit_glyph_row_to_buffer (0x080f0f70) 处理同一 row 方向写入, 关键区别在于 r3 额外传入显式前/背景颜色 nibble (低 4 位前景, 高 4 位背景), 每次迭代同时写两个相邻像素位置, 按 [0x02006ed0+0x15] bit3 区分 4bpp (nibble read-modify-write) 与 8bpp (byte write) 两路, 将像素写入 EWRAM 字形 tile 缓冲区.

## 参数签名
- r0: u8 glyph_col_bits — 字形列像素掩码 (bit7..bit0 对应 8 列, 置位 = 该列有像素); 经 `lsls/lsrs #0x18` 截取为无符号字节后存 sp+0x0
- r1: ptr src_row_a — 源字形数据行 A 指针, 函数内部 `asrs r6,r1,#0x3` 推导 x_tile_col, `& 0x7` 推导 x_within_tile
- r2: ptr src_row_b — 源字形数据行 B 指针 (与 r1 相差一行, 对应字形相邻两行)
- r3: u8 packed_color — 打包颜色参数: 低 4 位 [3:0] = 前景色 nibble (sp+0xc), 高 4 位 [7:4] = 背景色 nibble (sp+0x10); 经 `lsls/lsrs #0x18` 截取为无符号字节
- 返回: void (无返回值, 仅副作用)

## 副作用
- [EWRAM 0x02006ed0+0x0] 读取: VRAM tile 缓冲区基地址 (ptr)
- [EWRAM 0x02006ed0+0x8] 读取: VRAM tile 宽度 halfword; bits [13:8] 提取后得 tile_cols 数量
- [EWRAM 0x02006ed0+0x15] 读取: 字形渲染模式标志字节 (bit3=1 → 4bpp 路径; bit3=0 → 8bpp 路径)
- **4bpp 路径** `strb r2,[r6,#0x0]` @ 0x080f122e — 每个有效列, 对行 A 像素位置写 nibble-merged 字节 (ldrb 读旧值 → ands 清目标 nibble → orrs 注入前景/背景色 nibble → strb); 保留相邻 nibble 不被覆盖
- **4bpp 路径** `strb r2,[r6,#0x0]` @ 0x080f127e — 每个有效列, 对行 B 像素位置执行相同 nibble read-modify-write; 两次写操作对应同一字符的相邻两行
- **8bpp 路径** `strb r1,[r4,#0x0]` @ 0x080f12ec — 行 A 像素位置直接 byte 写入 (取 [sp+0x10 偏移] 处的颜色字节值)
- **8bpp 路径** `strb r1,[r4,#0x0]` @ 0x080f1312 — 行 B 像素位置直接 byte 写入

## 行级注释 (≤ 30 行精华, 按 ROM 地址排)
- @ 0x080f1190: `lsls/lsrs r0,r0,#0x18` — 截取 glyph_col_bits 为无符号字节, 避免高位垃圾影响 bit 测试
- @ 0x080f1196: `lsls/lsrs r3,r3,#0x18` — 同理截取 packed_color 字节
- @ 0x080f119a: `movs r0,#0xf; ands r0,r3` — 分离前景色 nibble (低 4 位) 存 sp+0xc
- @ 0x080f11a0: `lsrs r3,r3,#0x4` — 分离背景色 nibble (高 4 位) 存 sp+0x10
- @ 0x080f11a4: 读 DAT_080f1290 = 0x02006ed0 (gfx_ctx 基址) — 与 blit_glyph_row_to_buffer / blit_glyph_col_to_buffer 共享同一全局上下文
- @ 0x080f11a8: `ldrb r2,[r1,#0x15]; movs r0,#0x8; ands r0,r2` — 读 mode_flags bit3 判断 4bpp/8bpp; 与兄弟函数完全对称的分支入口
- @ 0x080f11ae: `beq LAB_080f1294` — bit3=0 (8bpp) 跳转到独立 8bpp 处理路径
- @ 0x080f11b0: 4bpp 路径初始化 r7=7 — 循环计数从 7 倒数到 0 (8 次迭代, 对应 8 列宽字形)
- @ 0x080f11ca: 循环头 `movs r0,#0x80; asrs r0,r7` — 生成当前列掩码位 (0x80 >> r7)
- @ 0x080f11d0: `ands r0,r4` — 测试 glyph_col_bits 中当前列是否有像素
- @ 0x080f11f4: `ldrh r4,[r4,#0x8]` — 读 gfx_ctx.tile_width halfword (偏移 +8)
- @ 0x080f11f6: `lsls r4,r4,#0x16; str r4,[sp,#0x1c]` — 保存移位后的宽度中间值
- @ 0x080f11fa: `lsrs r0,r4,#0x18; muls r0,r2` — tile_cols × row_byte_index = y_contribution
- @ 0x080f1200: `lsls r0,r0,#0x6` — 每行占 64 字节 stride (GBA tile 规格)
- @ 0x080f1206: `adds r2,r2,r0` — 行 A 基地址 = VRAM_base + y_offset
- @ 0x080f1228: `ldrb r1,[r6,#0x0]` — 读当前 tile 字节旧值, 准备 nibble 混合
- @ 0x080f122c: `orrs r2,r0` — 将前景色 nibble 注入正确位置 (低/高 nibble 由 x_within_tile & 1 决定)
- @ 0x080f122e: `strb r2,[r6,#0x0]` — **4bpp 行 A 写入**: nibble-merged 字节写回 VRAM 缓冲
- @ 0x080f1280: `rsbs r2,r2,#0; add r8,r2; add r12,r2` — 每列结束后更新高寄存器中的双缓冲索引
- @ 0x080f1288: `subs r7,#0x1; cmp r7,#0x0; bge` — 列循环控制, 从 7 倒数到 0
- @ 0x080f128e: `b LAB_080f131c` — 4bpp 路径完成后直接跳出, 不执行 8bpp 路径
- @ 0x080f1294: 8bpp 路径入口, r7=7 — 与 4bpp 路径同样的 8 次列迭代结构
- @ 0x080f12ec: `strb r1,[r4,#0x0]` — **8bpp 行 A 写入**: 直接 byte 写入 (无 nibble 混合)
- @ 0x080f1312: `strb r1,[r4,#0x0]` — **8bpp 行 B 写入**: 第二行字节写入
- @ 0x080f131c: 函数尾声, `add sp,#0x20; pop {r3,r4,r5}` 然后恢复高寄存器 r8/r9/r10

## 调用图
- 调用方 (caller): render_glyph_jp_single_layer (0x080f19a4) — 在 LAB_080f1aac 分支内, 当 sp+0x8 标志非零时调用本函数 2 次 (两次调用对应字形相邻两列); 为零则改调 blit_glyph_row_to_buffer
- 调用 (callee): 无 (纯叶子函数, 仅对 EWRAM 字形缓冲区有 strb 副作用)

## 置信度证据
- **high** 层 3 (数据 label 反推): `DAT_080f1290 = 0x02006ed0` 是 font_jp 模块全局字形渲染上下文, 已在 blit_glyph_row_to_buffer / blit_glyph_col_to_buffer / render_glyph_jp_single_layer 等所有兄弟函数中确认; 偏移 +0x0 = VRAM base ptr, +0x8 = tile_width halfword, +0x15 = mode_flags byte, 与已命名函数完全一致
- **high** 层 6 (调用图 hub + 兄弟对称): render_glyph_jp_single_layer 在 LAB_080f1aac 内实现单 flag_bit 对称分派 (`cmp r3,#0x0; beq → blit_glyph_row_to_buffer; bl → FUN_080f1180`), 两者为同一 row 方向操作的互斥变体; 与 feedback_symmetric_flag_bit_dispatch 模式完全吻合
- **high** 层 5 (副作用分析): 函数体内有 4 条 `strb` 写目标地址均由 `[0x02006ed0+0x0]` (VRAM base) 加行/列计算偏移得出, 属于 EWRAM 字形 tile 缓冲区写入; 两路 (4bpp nibble merge / 8bpp byte write) 与 mode_flags bit3 一一对应, 无歧义
- **high** 层 6 兄弟矩阵印证: blit_glyph_row_to_buffer (0x080f0f70) — 无显式颜色, 由上下文 nibble; blit_glyph_col_to_buffer (0x080f1070) — 列方向; 本函数 — 行方向 + 显式 packed_color nibble; 三者在同一 render_glyph_jp_single_layer 内形成完整的"行/列 × 隐式/显式色"矩阵
