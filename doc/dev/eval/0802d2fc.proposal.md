## plate comment (中文, ASCII 标点)
Function: 卡包选择界面 VRAM/调色板初始化 (卡组类型 A, 内部 key=0x2711). 无 APCS 输入. 入口立即 ldr r0, 0x2711 后调用 find_deck_record_index_by_key, 返回值 r0 为 deck_record_index; subs r4,r4,r0 计算 relative_deck_index (r4 在入口被 adds r4,r0 前已被 ldr 赋值为 0). 然后基于 relative_deck_index 计算 5 个 ROM 数据指针 (r5=调色板, r8/r9/r10=3 组 tile, r4=tilemap): 步进公式 r5=idx*9*32 + ROM_PALETTE_A, 其余使用类似乘法. 依次执行: (1) zero_fill_by_halfword x2 清空 OBJ VRAM 0x06000800/0x06001000; (2) upload_palette_rows_to_bg_vram(r5, 8); (3) 清 PAL_RAM 0x05000000; (4) upload_indexed_tile_rows_to_obj_vram(r8, 0x10); (5) upload_tilemap_rows_with_offset(r8_offset, 1, 0x10, 0x1e); (6) upload_indexed_tile_rows_to_obj_vram(r9=ROM_TILES+0x88*2, 0x14); (7) upload_tilemap_rows_with_offset(r4=tilemap, 2, 0x110, 0x1e). 与 init_pack_selection_tile_vram_default 结构完全对称, 差异在于所有 ROM 指针从 deck_record_index 动态计算而非固定常量.

Side effects:
- VRAM 0x06000800 (0x1000 bytes): zero cleared
- VRAM 0x06001000 (0x1000 bytes): zero cleared
- BG palette: deck-specific palette (8 rows) uploaded
- PAL_RAM 0x05000000: cleared to 0
- OBJ VRAM: deck-specific tile data uploaded

Constants:
- DECK_KEY_A = 0x2711 // find_deck_record_index_by_key 的内部 key (10001 decimal)
- PALETTE_TABLE_A = 0x09a1a52c
- TILEMAP_TABLE_A = 0x09a1dfac
- TILEMAP_TABLE_B = 0x09a98dec
- OBJ_VRAM_BASE_A = 0x06000800
- OBJ_VRAM_BASE_B = 0x06001000
- PAL_RAM_BASE = 0x05000000
- PALETTE_ROWS = 8
- TILE_ROWS_A = 0x10
- TILE_ROWS_B = 0x14
- TILEMAP_STRIDE = 0x1e
