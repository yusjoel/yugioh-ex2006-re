# Naming Proposal: 0x080177dc

## 提案
- **proposed_name**: setup_font_jp_ctx_obj_vram_row
- **confidence**: med

## plate comment (中文)
由 FUN_080183d0（名字输入页面字符串渲染包装层）在 text-box 初始化阶段调用，负责以 OBJ 区 VRAM（0x06010000）为目标，按 tile 行索引计算 VRAM 基址（基址 = 0x06010000 + r0 × 0x20），调用 init_font_jp_render_context 完成 104 字节渲染上下文清零和三项核心参数写入，之后追加置位 context[+0x15] bit5（0x20），并根据 r3 bit0 将 context[+0x8] bit1 设置为对应渲染模式标志，最后重新从 font_jp_base_table 读取函数指针写入 context[+0x04]。与使用 BG VRAM（0x06000020）的 FUN_08017798 形成对称：该函数覆盖 OBJ 精灵 VRAM 区，且 tile 行索引由调用方参数决定，适用于名字输入页面的多行文字 tile 槽配置。

## 参数签名
- r0: `u16 tile_row_idx` — OBJ VRAM tile 行索引，乘以 0x20（32 字节）后加到 0x06010000 得 VRAM 目标基址；调用方传入 0x17c 等值（典型 = FUN_08018400 传来的行偏移量）
- r1: `u8 width_tiles` — 文字绘制区域水平宽度（tile 数，如 6）
- r2: `u8 height_tiles` — 文字绘制区域垂直高度（tile 数，如 2）
- r3: `u8 render_flags` — 渲染模式标志位；bit0 控制 context[+0x08] bit1（0=单层渲染，1=双层/描边模式启用标志）
- 返回: void（无返回值，仅副作用写入 EWRAM font_jp 渲染上下文）

## 副作用
- `[0x02006ed0..+0x67]` := 0（经 init_font_jp_render_context → bios_cpu_set 清零全部 104 字节渲染上下文）
- `[0x02006ed0+0x00]` := `0x06010000 + tile_row_idx × 0x20`（VRAM 目标基址，OBJ 精灵 tile 区）
- `[0x02006ed0+0x08]` bits[2..9] := width_tiles（水平 tile 数，由 init_font_jp_render_context 写入）
- `[0x02006ed0+0x08]` bits[10..17] := height_tiles（垂直 tile 数，由 init_font_jp_render_context 写入）
- `[0x02006ed0+0x08]` bit0 := gSettings(0x02006c2c)&7 != 0 ? 1 : 0（bpp/语言模式标志，由 init_font_jp_render_context 写入）
- `[0x02006ed0+0x08]` bit1 := render_flags(r3) bit0（本函数追加写入，控制描边/双层模式）
- `[0x02006ed0+0x04]` := font_jp_base_table[idx]（渲染函数指针，idx 由修改后 context[+0x08] bits[0..2] 重新决定）
- `[0x02006ed0+0x15]` bit5 := 1（0x20，本函数追加置位；init_font_jp_render_context 只置 bit4=0x10）
