## plate comment (中文, ASCII 标点)
Function: 卡包选择界面 VRAM/调色板初始化 (卡组类型 B, 内部 key=0x4e20). 无 APCS 输入. 入口通过 prologue 完成高寄存器保存后立即 ldr r0, 0x4e20 调用 find_deck_record_index_by_key, 返回值 r0 为 deck_record_index; subs r4,r4,r0 计算 relative_deck_index (r4 在入口 adds r4,r0 前已被初始化为 0). 然后基于 relative_deck_index 计算 5 个 ROM 数据指针: r5=调色板 (PALETTE_TABLE_B=0x09953cec, 步进 idx*9*32), r10=tilemap A (0x09956c2c), r9=tilemap B (0x099ba04c), r8=tilemap C (0x099aac2c), r4=tilemap D (0x09a0e04c). 依次执行: (1) zero_fill_by_halfword x2 清空 OBJ VRAM 0x06000800/0x06001000 (各 0x800 halfwords); (2) upload_palette_rows_to_bg_vram(r5_deck_palette, 8); (3) 向 PAL_RAM 0x05000000 写 0 (清背景色); (4) upload_indexed_tile_rows_to_obj_vram(r8, 0x10); (5) upload_tilemap_rows_with_offset(r8_offset, 1, 0x10, 0x1e); (6) upload_indexed_tile_rows_to_obj_vram(r9+0x88*2, 0x14); (7) upload_tilemap_rows_with_offset(r4=tilemap, 2, 0x88*2, 0x1e). 与 init_pack_selection_tile_vram_by_deck_a (0x0802d2fc) 结构完全对称, 仅 deck_key 与 ROM 表基址不同: deck_key_B=0x4e20 vs deck_key_A=0x2711.

Side effects:
- VRAM 0x06000800 (0x1000 bytes): zero cleared
- VRAM 0x06001000 (0x1000 bytes): zero cleared
- BG palette: deck-B-specific palette (8 rows) uploaded
- PAL_RAM 0x05000000: cleared to 0
- OBJ VRAM: deck-B-specific tile data uploaded
- BG tilemap: deck-B-specific tilemap data uploaded

- TILE_ROWS_A = 0x10
