# Naming Proposal: 0x0803b618

## 提案
- **proposed_name**: get_zone_card_attribute_by_type
- **confidence**: med

## plate comment (中文, ASCII 标点)
根据区域类型代码 (r1, [0xb..0xf]) 派发到 5 个 case, 读取对应玩家 (r0) 在指定牌组/区域格 (r2/r4) 的卡牌属性并返回 u16. case_d (r1=0xd): 从 0x0201c740 (gP1CardZone?) 表读位域后调用 find_effect_node_in_zone; case_f (r1=0xf): 从 gP1LifePoints+0x788 读半字, 检查 [byte]==0x40/0x80/其他, 返回 0/1/bit[9]; case_b (r1=0xb): 检查实体 ID 匹配后调用 get_player_deck_flag_bit1; case_c (r1=0xc, 0xe): 返回固定 0 或 1; default: 从 0x0201bc54 或 0x0201c510 表读 u16 at [+8]. 被大 hub FUN_0803ccac 及多个 duel_field 函数在构造卡面信息包前调用.

Constants:
- 0x868 = 玩家结构体 stride
- 0x0201c740 = gP1CardZone base (EWRAM)
- 0x12a1 = case_d 用的字段偏移量
- 0x0f1*8 = 0x788 = case_f 的 LifePoints 内偏移
- 0x0201bc54 = default case 卡属性表基址
- 0x40 = case_f byte 比较阈值 A (bit6; 可能代表 STATUS_EQUIPPED 或效果冻结标志, asm:67980)
- 0x80 = case_f byte 比较阈值 B (bit7; 可能代表 STATUS_ACTIVE 或激活标志, asm:67982)

## 参数签名
- r0: u32 packed_player_id; bit0 = player index [0..1]
- r1: u32 zone_type_code; 区域类型 [0xb..0xf]; 超出范围走 default 路径
- r2: u32 slot_or_card_index; 区域格索引, 具体语义随 zone_type 变化 [0..9]; 从 caller (0x0803cef8 asm:71024-71025) packed_word bits[13:6] 提取 (lsls r2,#0x12 / lsrs r2,#0x18), 理论 8-bit; 场地格实际最多 10 格 (monster[0..4]+spell/trap[5..9]), case_d 路径以 slot*4 访问 0x0201c740 表 (asm:67935), case_f 以 slot*2 作偏移 (asm:67968), 均对应 5 格或 10 格区域故上界 [0..9]
- 返回: r0 = u16 卡牌属性值; 含义随 zone_type_code 而异 (见 plate)

## 副作用
无 (只读)
