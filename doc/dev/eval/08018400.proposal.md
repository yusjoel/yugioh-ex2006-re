# Naming Proposal: 0x08018400

## 提案
- **proposed_name**: zero_obj_vram_tiles
- **confidence**: high

## plate comment (中文)
render_jp_text_to_vram_obj 的清屏前置函数。在 name_input 页面每次向 OBJ 精灵层写入 JP 字形前，由 addr 0x08017b44（tags: duel_field;font_jp;game_str;settings，场景文字行渲染，调用 3 次）和 addr 0x08018774（tags: font_jp，当前选中字符高亮，调用 1 次）先调本函数清零目标 tile 区域，再紧接着调 render_jp_text_to_vram_obj 写入字形像素。本函数通过 BIOS CpuSet（SWI 0x0B）以"fill 模式 + 32 位字宽"将 OBJ VRAM 区段 `[0x06010000 + tile_idx*32, +num_tiles*32)` 全部填零，确保旧字形像素被擦除后才进行新一轮渲染。

## 参数签名
- r0: `u16` tile_idx — OBJ 精灵 tile 起始索引（0-based），函数内乘以 32 得 VRAM 字节偏移，有效范围 [0..0x3FF]（OBJ VRAM 共 16 KB = 512 tiles）
- r1: `u16` num_tiles — 要清零的 4bpp tile 数量；调用方传 0xc（12 tiles = 384 bytes）或 0x22（34 tiles = 1088 bytes）；函数内乘以 8 换算成 32 位字数后传给 bios_cpu_set
- 返回: r0 = void（`pop {r0}; bx r0` 是 Thumb 无返回值惯用写法，r0 值为返回地址，调用方立即以 MOV r0,r10 覆盖）

## 副作用
- [OBJ VRAM 0x06010000 + tile_idx×32, 共 num_tiles×32 字节] := 0x00000000（通过 bios_cpu_set fill 模式批量清零 4bpp sprite tile 像素数据；每次调用约擦除 12–34 个 tile 的字形残留）
