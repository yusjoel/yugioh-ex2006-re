# Naming Proposal: 0x0804caf0

## 提案
- **proposed_name**: init_card_sprite_row_entry_alt
- **confidence**: med

## plate comment (中文, ASCII 标点)
初始化 sprite row 条目的第二变体. 与 init_card_sprite_row_entry_v1 (0x0804c958) 结构完全对称:
同样 memset 清零 0x18 字节, 将 r0 (card_id) 写入首 halfword, 将 r1 (attr_packed u16) 中的 OAM 字段拆包写入 attr0/attr1/attr2.
核心差异: 本变体将 r1 (截断后的 attr_packed) 先保存于 sp[0x18] (str r1,[sp,#0x18]), 在 memset 后再从 sp[0x18] 恢复, 而 v1 通过 r10 (callee-save alias) 传递. 两者调用同一组 dispatch_card_effect_activation + submit_slot_card_sprite_row_entry.
三个 caller 与 v1 完全相同: FUN_08095ba8/FUN_08095ca0/FUN_08095d84.

Constants: base=0x0201b290, slot_count_offset=0x4cc (同 v1), attr_mask_1ff=0x1FF, attr_mask_803f=0xFFFF803F, entry_size=0x18.

## 参数签名
- r0: u16 card_id [0..0x172f] (游戏总卡数上界; 字段位宽 13-bit 静态上界 0x1fff) - 写入 entry[0..1] (halfword); 由调用方从 gDuelFieldSlots 低 13 位提取 (lsls/lsrs #0x13)
- r1: u16 attr_packed - OAM 属性打包字 [0..0xffff], 先截断再存 sp[0x18] 后使用
- 返回: r0 = void (以 bx r0 结束; 无固定返回值)

## 副作用
- memset 目标结构体 0x18 字节为 0
- strh [r0_target] := card_id halfword
- strb [target+0x2], strb [target+0x3]: OAM 字段拆包写入
- strh [target+0x4]: attr2 写入
- 若激活成功: 调用 submit_slot_card_sprite_row_entry

## 置信度 / 升级路径
- 静态已确认: 两变体在 caller 中的选择逻辑. 静态比较 FUN_08095ba8 内两条 bl 前的 r1 构造: 调用 FUN_0804c958 (v1) 时 r1 来自单次 `ldrh r1,[r0,#0]` (直接 16 位字段加载); 调用 FUN_0804caf0 (alt) 时 r1 由多次 `orrs r0,r1` 合并多个 halfword 字段构成 (更宽的打包 attr). 结论: alt 变体处理跨多个槽字段合并的 r1, 与 v1 处理单 ldrh 字段的路径不同; 两者均从同一 gDuelFieldSlots 基础偏移读取 card_id [0..0x1fff].
