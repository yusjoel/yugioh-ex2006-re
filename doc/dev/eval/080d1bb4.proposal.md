# Naming Proposal: 0x080d1bb4

## 提案
- **proposed_name**: dispatch_zone_card_anim_by_type
- **confidence**: med

## plate comment (中文, ASCII 标点)
当决斗场地卡槽进入"激活/渲染"阶段时, 由 tick_zone_card_anim_state (0x080d2390) 或 FUN_080d4268 直接调用. 从 gDuelCtx+0x2f53 提取高 3 位 (bits[7:5]) 作为 card_high, 从 gDuelCtx+0x2f54 提取低 5 位 (bits[4:0]) 左移 3 后与 card_high 合并, 得到组合类型码 [0..6]; 若 >6 则跳转到 LAB_080d21ce 处理异常路径. 正常路径以类型码为索引查询 PTR_DAT_080d1c10 (7 项函数指针表), 将目标地址存入 r8, 随后通过 bx r8 调用对应的子渲染处理程序. 副作用: 通过子处理程序间接写入 VRAM 及卡槽显示状态字.
Constants: DUEL_CTX=0x02020160; CARD_STATUS_OFFSET=0x2f53; CARD_LOW_OFFSET=0x2f54; CARD_WORD_OFFSET=0x2f58; JUMP_TABLE_PTR=0x080d1c0c; TYPE_COUNT=7; TYPE_MASK_HIGH=bits[7:5]; TYPE_MASK_LOW=0x1f.

## 参数签名
- r0: (void, discarded at 0x080d1bc0 by movs r0,#0x1)
- 返回: r0 = u32, 尾调用子处理程序的返回值; caller tick_zone_card_anim_state 在 bls 分支后忽略此值 (固定以 movs r0,#0x1 覆盖); 若从 FUN_080d4268 调用, r0 语义由各子处理程序决定 (子处理程序集体未命名, 置信度 med).
- 备注: gDuelCtx 基址由字面量池内部加载 (0x080d1bc4 ldr r2, DWORD_080d1bf8), 不是调用方传入; r8/r9/r10 通过 prologue (.hword 0x4657/0x464e/0x4645) 纯 callee-save 保存 (r10->r7, r9->r6, r8->r5 后 push), 不作为输入参数.

## 副作用
- [gDuelCtx+0x2f58+field] 及相关 VRAM/OAM 写入: 通过 7 个子处理程序间接执行, 具体内容由类型码决定
- [0x080d1c2c..0x080d21ce]: ROM INCBIN 区间内的子处理程序执行各自副作用
