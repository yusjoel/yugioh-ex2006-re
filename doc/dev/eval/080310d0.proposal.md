## plate comment (中文, ASCII 标点)
在两组 (player=0 和 player=1) 的槽位列表中顺序搜索与目标 ID 匹配的条目, 返回其逻辑索引. 函数以 gP1LifePoints + 0x87<<5 = gP1LifePoints+0x10e0 为第一组列表基址, 将 r0 (player_side bit0) 存入 r6, r1 (target_id) 存入 r5 和 r12 (callee-save via mov r12,r1). 外层循环 r4=[0..1] (两组列表), 内层循环 r3=[0..0x7e] (127 条目, step=8 字节每条目). 每条目读 halfword, 提取低 13 位 (lsls#0x13/lsrs#0x13), 与 r5 比较; 命中时返回逻辑索引 r1 = r6 XOR r4 (考虑 player_side). 未命中返回 0 (movs r0, #0). 由 4 个 caller 调用 (含 card_data/duel_field 场景).

Constants: gP1LifePoints=0x0201c4e0, base_offset=0x87<<5=0x10e0, entry_size=8 bytes, entry_count=0x7f=127 per list, list_count=2, id_bits=13 (低 13 位).

## 参数签名
- r0: u32 player_side [0..1] (参与搜索的主体 player; 保存到 r6 用于 XOR 计算返回索引)
- r1: u16 target_id [0..0x1FFF] (低 13 位目标 ID; 通过 lsls#0x13/lsrs#0x13 掩码匹配)
- 返回: r0 = u16 player_side_result (命中时为 r6 XOR r4 = player_side XOR list_idx [0..1]; 未命中时为 0 (movs r0,#0); 注: caller 0x0804c76c 在 bl 前先独立检查 card_id AND 0xFFFF 非零再消费 r6, 故 0 在该 caller 中作"未命中"标志不与 player_side=0 命中歧义 -- caller 通过 card_id 有效性检查(0x0804c792 ands r0,r5 + cmp r0,#0x0)分离两种 0 含义)
