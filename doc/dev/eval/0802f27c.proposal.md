# Naming Proposal: 0x0802f27c

## 提案
- **proposed_name**: count_zone_chain_eligible_cards
- **confidence**: med

## plate comment (中文, ASCII 标点)
遍历 gDuelFieldSlots (0x0201c510) 中指定槽 (side+slot_index) 的节点链, 统计满足条件的节点数量. 每个节点需满足: (1) zone_type<=5 (有效区域); (2) 节点关联卡牌的 card_id == r2 (target_card_id); (3) gDuelFieldSlots+0x10 中对应槽的某状态位未置 1; (4) 根据 r3 (effect_eligible) 和 sp[0] (fieldspell_eligible) 决定是否进一步检查 get_card_extended_stat_field6 和 check_card_field5_is_nonzero. 节点的"关联卡牌"通过节点自身记录的 zone_type/zone_index 反向查到 gDuelFieldSlots 对应槽读出 card_id. 两个 caller 对应两种使用场景: 简单版 (FUN_0802f394, sp[0]=0) 和完整版 (FUN_0802f3a8, 传入实际 eligibility 标志).

Constants:
- 0x0201c510 = gDuelFieldSlots (槽基址)
- 0x0201c520 = gDuelFieldSlots+0x10 (状态位数组)
- 0x0201d9c0 = gDuelNodePool (节点池)
- 0x868 = player stride; slot_entry = 20 bytes
- 0xfffa0000 + 0xffffeb50 = 反向映射 gDuelNodePool -> gDuelFieldSlots (差值 0x14B0)
- 0xfffa0000 = 用于 (zone_nibble<<16 + 0xfffa0000)>>16 计算 zone 偏移的魔数 (net 0xfffa + zone_nibble)
- field6==0x16 = 融合/特殊召唤限制标记; field6==0x17 = 另一种限制标记

## 参数签名
- r0: u32 packed_player_id -- bit0=side (0=P1, 1=P2)
- r1: u32 slot_index -- 槽索引 [0..11]
- r2: u16 target_card_id -- 目标卡 ID, 与节点关联卡的 card_id (低 13 bit) 比较
- r3: u32 effect_eligible -- 效果激活资格标志 (bool, 调用方 check_slot_card_effect_eligibility 结果)
- sp[0] (第5参数): u32 fieldspell_eligible -- 场地魔法资格标志 (bool, 0=不检查)
- 返回: r0 = u32 -- 满足全部条件的节点计数 [0..max_chain_len]

## 副作用
无 (只读遍历, 无 EWRAM 写入)
