# Naming Proposal: 0x080f1720

## 提案
- **proposed_name**: render_glyph_indexed_dual_layer
- **confidence**: med

## plate comment (中文)
由 FUN_080f21e8（font_jp 渲染调度函数）在检测到字体状态标志 `[0x02006ed0+0x15] & 0x10` 后调用，用于直接以 u8 字形索引（0–255）查询 ROM 字体位图表（窄字 10 字节/条目，宽字 12 字节/条目），将对应字形以 4bpp 双写方式展开并写入 OBJ tile 缓冲区（通过 `*[0x02006ed0]` 指向的目标地址）。与 `render_glyph_jp_dual_layer` 的区别在于：本函数跳过了 `char_code_to_glyph_index` 映射，接受调用方已预先解析的字形索引，适用于小字符集（ASCII/符号集）的快速渲染路径。双写（两次 `str` 间距 `+0x20`）对应同一字形行在 sprite tile 内的两个 4bpp 横向分区。

## 参数签名
- r0: u8 glyph_idx — 字形索引，范围 [0, 255]，直接用于 `font_table_base + glyph_idx * entry_size`；不经 char_code_to_glyph_index 映射
- r1: i16 x_pos — 渲染目标像素横坐标，用于计算 OBJ tile 列偏移（`x_pos >> 3` = tile 列，`x_pos & 7` = tile 内像素偏移）
- r2: i16 y_pos — 渲染目标像素纵坐标，用于计算 OBJ tile 行偏移
- r3: u16 attr_flags — 属性标志，低 8 位传入 `sp[0]`（影响字形行像素的 nibble 选择，具体含义待 runtime 验证）
- 返回: void（无返回值，仅副作用）

## 副作用
- `[*[0x02006ed0] + tile_row_offset]` := 4bpp 字形行数据（每次循环写两个 32-bit VRAM word，地址间距 0x20，合计写 `r4` 次，`r4` = 10 或 12，由字体宽度决定）；写入目标为 OBJ sprite tile 缓冲区
- 无 IO 寄存器（`0x04000000+`）操作
